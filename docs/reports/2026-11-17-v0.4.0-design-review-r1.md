# v0.4.0 design note — review r1

Reviewer (Opus, high), 2026-11-17, spec/plan mode. Spec: `docs/specs/2026-11-17-v0.4.0-new-ui-design.md` (uncommitted, branch feat/v0.4.0-ui at origin/main 84933416). Filed by the controller: the reviewer's write was refused by the reports hook (worktree then outside `.claude/worktrees/`; since moved to `.claude/worktrees/v040-ui`).

**Verdict: FAIL** — every fix is to the spec text; nothing needs a redesign.

## Blocking

- **B1 — every upgrading student gets a second, native title bar.** `main.rs:90` and `:148` use the window-state plugin with default flags, which include restoring the frame (`DECORATIONS`). Every 0.1.x install saved `"decorated": true`, so on first launch of 0.4.0 the plugin turns the native frame back on over `decorations: false`; the plugin then saves the bad state again on close. Fix: drop `DECORATIONS` from the flags in both builders, pin it with a test, and add an upgrade-path check to the live proof.
- **B2 — the ported site shows prices nobody charges (blocking for the tag).** The site M9b ports says $12.99 every 4 weeks, a 14-day trial and a 30-day money-back. Billing charges $9.99 a month or $69.99 a year with a 7-day trial (`billing-checkout/index.ts:20`, `handler.ts:59`). The wizard the spec keeps word for word also says $9.99 and 7 days (`app/static/index.html:123,135-136`). Needs Quinn's decision before the tag.

## Important

- **I1 — an unreadable task would vanish silently.** §8 retires `console_js_is_one_render_function_per_region_and_uses_invoke`, which holds the pin that an unreadable task never disappears without a line (`static_assets.rs:116-119`). §4 maps nothing for `unreadable` or `warnings`.
- **I2 — Home can no longer say the day doesn't fit.** The overload fields (`verdict.overflow_sentence`, `meter.spill_*`, `give_text`) are unmapped; VISION's MVP list includes "must-do work against the day's capacity" (`VISION.md:212-214`).
- **I3 — Waiting shows only the cards.** Dropped: the digest count, the hidden-amendment count, the snoozed count, the "only clear when the digest is empty too" rule, `must_do.amendments`, card flags and decision notes. A pending events digest would read as "clear".
- **I4 — the first-run screen is wired to the wrong place.** `first_run` sits on the envelope, `state` is null during the first run (`commands.rs:524-531`), and that page polls every 3 s, not 60 s. As written, a new student's first screen throws or stays blank.
- **I5 — re-consent can trap a student who declines.** A full-window sheet would cover `#settings`, so Delete my data can't be reached without accepting (pins at `static_assets.rs:3295-3311`). The start-control lock while the update is owed must also reach every new control.
- **I6 — "Clear through Thu 12" can be false.** Home's `today` view has no full task list, so a task with slack that missed Recommended is invisible to that line. Derive it from `ahead.buckets[].items`.
- **I7 — a red commit can still be tagged.** `release.yml` and `release.ps1` run no tests and don't check the tagged commit's CI. The live proof never exercises the real 0.1.5 → 0.4.0 upgrade.
- **I8 — parallel lanes share files.** The wizard panels are markup in `index.html` (M2's), yet M5b and M6 must edit it; all M8a pins go into one shared `ui_next.rs` while six lanes run.
- **I9 — the telemetry view name isn't fixed.** `class/<slug>` is refused by telemetry; `class:<slug>` would tell telemetry which courses the student takes.
