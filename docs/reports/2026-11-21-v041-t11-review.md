## Findings

**I1 (Important). `docs/reference/price-change.md:99-102`, step 4.** Step 1's reuse rule is stated only for
test mode; step 4 says flatly "Quinn creates the live Price ... the main session sets the production
variable". Scenario: 1299 to 1499 under `stay`, later back to 1299. Followed literally, Quinn creates a second
live Price at 1299 (the old one was archived in step 7 of the earlier change, so creating looks natural), and
`STRIPE_PRICE_FOUR_WEEKLY_1299` is re-pointed to it. The `stay` subscribers still on the original Price now
match no catalog id: `lookupPrice` returns null and the webhook writes `plan: null` on their next event
(`stripe-webhook/handler.ts:154`), and their emails fall back to the unknown-price text. It breaks the
runbook's own line 25-26 ("a variable names one Stripe price forever ... never re-points one"). D16 step 4
(note line 681) has the same gap, so the note should take the same line. Fix: in step 4, "or, if the key has
been sold at this amount before, Quinn unarchives that live Price (step 1's rule: never a second Price at the
same key and cents), and the production variable keeps its id; the variable is set only for a new Price."
