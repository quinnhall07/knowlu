## Findings (all Minor)

**M1. `engine/tests/workflows.rs:665` — the main-only pin can be fooled by the `case` branch's `exit 1`.**
- Scenario: someone deletes `exit 1` at `.github/workflows/site.yml:64`, or changes it to `exit 0`. The step still contains `!= "refs/heads/main"` and an `exit 1` (from the `case` at `:70`), so every pin stays green. A later dispatch from a branch cut from that `main` then deploys the branch's `site/`, legal pages included, to knowlu.com. This is the one pin gap that does not show itself on a normal run.
- Fix: assert that the text between `!= "refs/heads/main" ]; then` and the next `fi` contains `exit 1`. Or assert `s.matches("exit 1").count() == 2`.

**M2. `engine/tests/workflows.rs:712`, `:718`, `:791` — the pins check that a comparison exists, but not which way it points.**
- Scenario: flipping `!=` to `=` at `site.yml:96` or `:107`, or dropping the `!` at `:115`, passes every pin. Each flip would refuse the normal case, so the first run would expose it; that is why this is Minor.
- Same class: `:680` only checks the prefix of the view line, so `gh release view --json tagName … v0.1.5` would pass. The newer-tag check then refuses that run.
- Fix: pin the three condition lines exactly: `if [ "$newest" != "$TAG" ]; then`, `if [ "$open" != "0" ]; then`, `if ! git diff --quiet "$TAG" HEAD -- site/privacy.html; then`.

**M3. `engine/tests/workflows.rs:215-219` and `:800` — nothing stops a Pages deploy outside the two guarded wrangler-action steps.**
- Scenario: someone adds a step `run: npx wrangler pages deploy site --project-name knowlu --branch main` ahead of the guards. No pin sees it. That deploy drops the installer before any guard has run.
- Fix: `assert_eq!(code.matches("pages deploy").count(), 2)`.

**M4. Report concern 2 (`t10-report.md:83`) is factually wrong.**
- Git's version sort compares "v0", then '4' against '.', and returns -1. So `v041-red/t10` and every `v040-*` tag sort *before* `v0.4.0`. If pushed, they are ignored; they do not block the run.
- They would sort after the release tags only once releases are `v1.x` and lanes use tags like `v1xx-*`.
- Fix: correct the report so nobody narrows the `v*` glob or changes the tag habit because of it. No code change.
