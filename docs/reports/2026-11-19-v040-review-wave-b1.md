## Important

**I1. A student whose grades Knowlu cannot read sees "No scores" on every class.** Fix in code, on the T13 branch.
- `classes.js:41-45` (`gradeText`) and `class.js:70-82` (`gradeBigHtml`, `gradeBodyHtml`) send any class with no `S.grades` entry to `KnowluFmt.grade(null, false)`, which returns "No scores". The class page also draws Hide beside it (`class.js:81`).
- `grades_status` says when there is nothing to read: `available: false` for a school that is not on Blackboard, and `connected: false` before Connect (`grades.rs:378-389`; `availability_with` at `:57-66` is Blackboard-only).
- The shipped strip handled these cases. It drew `gradesUnavailableHtml()` when grades were not available, and "Connect Blackboard to see your grades" when not connected (`console.js:1348-1363`). The new pages lose that difference.
- Scenario 1: a friend on Canvas, the most common platform in the demand list, opens Classes. Every row's Grade reads "No scores". Each class page shows a large "No scores" and a Hide button. That says the student has no scores, which is false; Knowlu just cannot see them.
- Scenario 2: a Blackboard student who has not pressed Connect sees the same, with no hint that connecting would fill it in.
- Note §4 defines "No scores" only for `basis: none`, which is an entry that exists with nothing graded. It never defines it for a missing entry.
- Fix: when a class has no `S.grades` entry and `KnowluData.last("grades_status")` is not `available && connected`:
  - the list cell is blank;
  - the class page's Grade line is blank, the body drops Hide and the figure, and shows one line that points to Settings > Sources. Reuse the shipped wording, "Connect Blackboard to see your grades", only when `available` is true.
  - Add a `t13-unavailable` envelope (`available: false`) and a `t13-unconnected` envelope, plus a pin that "No scores" is drawn only for an existing entry or a connected source.

## Minor (fix in code unless marked)

**T13 / T9**

- **M1. Classes and the class page repaint on every poll, so keyboard focus is lost every minute.**
  - `classes.js:115` redraws the whole list (`#cl-groups` innerHTML) on every `onPoll`. That hook fires up to three times a minute (state, `grades_status`, `mail_status`), even when nothing changed.
  - `class.js:282` does the same for the Grade body.
  - `class.js:287` (`update` → `refreshBreakdown`) closes and reopens the panel on every new revision, which resets the breakdown's scroll position and any focus inside it.
  - Scenario: a keyboard user tabs to a class row. When `grades_status` lands, focus drops to `<body>`.
  - Fix: keep the last hidden flag and the last `grades_status` object, and redraw only when they change. Skip `refreshBreakdown` when the course's `S.grades` entry is unchanged (compare its `JSON.stringify`).
- **M2. Lock in loses focus at every step.**
  - These lines rebuild the stage or the time half under the pressed control: `lockin.js:232` (Done → beat), `:246` (Undo), `:253` (Start next), `:259` (Break now), `:265` (Skip break).
  - Scenario: a keyboard user presses Done. Focus falls to `<body>`, and Start next, the only way forward, is several Tab presses away.
  - Fix: after each `draw()` or `drawTime()`, focus the new primary control:
    - Start next on the beat;
    - Done after Start next or Undo;
    - Home on the closing page;
    - Skip break or Hide time after the break buttons.
- **M3. `lockin.css:55` `span.ck { cursor: default; pointer-events: none; }` is unscoped.** All page CSS loads into one document. It already matches Tasks' done mark (`tasks.js:23`, `<span class="ck tk-done">`), and it would disable any later `span.ck` that is meant to be interactive. This is the same class of issue as wave-A M3. Fix: `.lk-stage span.ck`.
- **M4. One Lock in pin is weaker than it reads.** `ui_lockin.rs:29` asserts `contains("queueFrom(ctx.state, ctx.arg)") || contains("ctx.arg")`. Any mention of `ctx.arg` satisfies it, and the code's actual text (`ctx.arg || ""`) only matches the second half. Fix: assert `queueFrom(ctx.state, ctx.arg || "")`.
- **M5. Nothing drives the break.** `t09.py` checks the clock reads 25:00 and checks Hide time, but never runs the clock to "Break ready" → Break now → Skip break. `ui_lockin.rs` checks only the words. I read the logic in `tick`, `takeBreak` and `skipBreak` and it is sound. Fix: in `t09.py`, use Playwright's `page.clock.install()` and `fast_forward("25:00")`, then assert the label, Break now, the Skip break round trip, and that the focused total does not count the break.

**T21**

- **M6. Focus is not moved when the wizard changes panels.**
  - `wizard.js:234` already notices a new step (`SHOWN_STEP`).
  - After Google or code sign-in, `wizGo(2)` (`:598`, `:626`) moves on while focus is on a control that is now hidden, so focus falls to `<body>`.
  - Otherwise focus stays on Next, below a panel a screen reader has not heard.
  - Today's wizard behaves the same, so this is not a regression, but the restyle is the cheap moment to fix it.
  - Fix: give each panel's `h2` `tabindex="-1"` and focus it in that `SHOWN_STEP` branch.
- **M7. Every picker row's button is named only "Open".** `picker.js:46`. With two profiles, a screen reader hears "Open, Open". Fix: `aria-describedby` on the button pointing at that row's `.pick-name`, which needs an id built from `h(p.id)`.
- **M8. The green commit's message names a change that is not in it** (record only). `afbbc841` says "checks/t21.py: Playwright waits capped at 5 s and its lines flushed", but that commit touches only the four page files; the 5 s waits are already in red `757aa89f`. The squash body carries the red SHA and its failure reasons, so drop that line when squashing.
