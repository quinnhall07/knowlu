## Important

**I1. The Status dot ignores `grades_status`, which arrives after the repaint, so a signed-out grade source never shows.**
- `app/static/next/js/data.js:103-105`: `arrived()` emits, then `grades_status` is fetched.
- `app/static/next/js/shell.js:341-345`: `drawStatus()` runs only from `KnowluData.on`, which fires only on a new `revision`.
- The header at `shell.js:21` says `status()` redraws "also on every poll", but nothing calls it.
- Scenario:
  1. The student's LMS session expires and `grades_status` answers `signed_out: true`.
  2. No note changes, so `revision` stays the same.
  3. The red dot and the "Grades: Signed out" row never appear until something else changes the vault, which can be all day.
- The same happens on every launch: the first paint is drawn before `LAST.grades_status` exists.
- This breaks VISION's "failures visible" and the dot's job under P11.
- **Fix in code:** call `KnowluShell.status()` when the `grades_status` answer lands, or fire an after-poll hook. `mail_status` needs the same hook for T19.

**I2. A failed poll is invisible to every surface, and during the first run it drops the 3 s cadence.**
- `data.js:106`: the rejection handler does nothing. It records nothing in `LAST`, calls no subscriber, and does not re-arm `FIRST_TIMER`.
- An `{ok: false, state: null}` envelope (`data.js:103`) is also silent: it lands in `LAST.state`, but no one is told.
- The old page showed "The engine did not answer." (`console.js:1621-1625`). It also re-armed the first-run timer after a rejected call (R-C1c-exec-8a M1).
- Scenario 1: the engine sidecar stops answering. The page keeps its last state with no word, and T19's sync/update line cannot learn this without editing `data.js`, which plan §3 forbids.
- Scenario 2: one rejected `state` call during the first run. The next try comes from the 60 s interval, not 3 s.
- **Fix in code:**
  1. Re-arm `FIRST_TIMER` on a rejection while `FIRST` is set.
  2. Add one documented hook for the poll's outcome (for example `KnowluData.onPoll(fn)` with `{ok, error}`), or make `last("state")` cover the rejection, and say so in the header.

**I3. The base envelopes carry `vault-full`'s weekly class times (rule 1, and the user rule against copying a real schedule into a fixture).**
- `scripts/ui-fixture/make_base_courses.py:123-125` copies every `config/` file except `ingest.yaml`, including `week_template.yaml`.
- That file's `classes:` blocks carry comments that name real-looking course codes (`GN 103`, `CS 100`, `PH 106` …). The fixture's own config talks about "Quinn's request" (`planning.yaml`), which suggests it came from a live vault.
- The engine turns those blocks into `kind: "class"` entries in the envelopes, for example Friday 12:00-12:50 and 13:00-13:45 in `envelopes/base-courses-today.json:520-537`, and the same in every set.
- No course name leaks, but the envelopes are a new artifact carrying a person's weekly class schedule. The plan allowed `config/` without noticing this.
- **Fix in code:** write an invented `week_template.yaml` (invented times, no comments) in `base_vault()`, keep copying only `events.yaml`, `planning.yaml` and `runners.yaml`, then regenerate.

## Minor

**M1. A same-view route change throws away a held reorder (R28 ruling).**
- `data.js:134`: when the view does not change, `HELD` is set to null instead of being painted.
- Scenario:
  1. The pointer rests on a Tasks list while a reordered state is held.
  2. The student clicks Calendar, which uses the same `all` view.
  3. Calendar mounts with the older state and stays stale until the next focus or the 60 s poll.
- Not forgetting `S` on a same-view change is the right ruling: no blank, no refetch, and the hold R28 guarded against cannot happen without a new paint.
- **Fix in code:** `if (HELD) { paint(HELD); }` in that branch.

**M2. A write's state is adopted even after the view has changed.**
- `data.js:115`: `call()` adopts `env.state` without checking that `a.view` is still `stateView()`. The poll does check (`data.js:99`).
- Scenario:
  1. The student checks a task on Tasks (`all`).
  2. They click Home before `set_fields` answers.
  3. Home's `today` poll paints first, then the `all` state is adopted over it.
  4. Home shows a horizon state until the next poll.
- **Fix in code:** adopt only when `a.view === stateView()`, and otherwise call `poll()`.
