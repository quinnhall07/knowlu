## M5: is the shape rule right?

As far as I know them, Checkout Session ids are `cs_test_` or `cs_live_` followed by a long run of ASCII letters and digits. Both prefixes match `^cs_[A-Za-z0-9_]+$`, because the underscore is in the class. I know of no Checkout Session id with a hyphen or any other character. **I cannot confirm the alphabet against Stripe's own documentation**: Stripe does not publish its id format as a contract.

**If a real id fell outside the rule:** every returning customer with an open page would be refused, since the whole list is refused. No new page is made while that happens, so the student would be blocked until the old page lapses, 24 hours by default. The next page they open would block them again the same way. The failure is closed (no charge) but it stops sales, so it belongs in the proofs:
- **Staging proof (test mode):** record two real listed session ids and show that each matches the rule. The proof's existing step already does this implicitly: two expires must happen and no `LIST_REFUSED` may appear.
- **First production checkout after release (live mode):** staging cannot produce a `cs_live_` id, so the release smoke must show that a second press on a live account expires the first page and does not answer `LIST_REFUSED`.
