## 1. VISION, the two rules, the contract list

- **VISION.** Grades as text, never a ring; failures visible (unreadable notes, overload, the Status
  dot); checks act at once with Undo, Knowlu's proposals wait in Waiting; nothing the student sees needs
  the network; preferences hold no plan data (note §12).
- **Rule 1, no single-user assumption.** No name, class, vault, account or machine path in a shipped
  file, test, fixture or doc; the mockups' made-up names do not ship (pin `ui_shell.rs::no_mock_data_or_review_aid_ships`);
  test data uses invented course codes (`ABC 101`), never Quinn's classes.
- **Rule 2, no frozen reference regenerated.** The eight Python references and the three
  `surface-today-*.json` stay byte-identical; T3 proves it by running `surface_oracle.rs` unedited. The
  fixture harness (T5c) reads the three references and never writes them.
- **The contract list.** Nothing in this plan edits a file on it (`engine/src/{write,journal,…}.rs`,
  `app/src/{credentials,account,updates}.rs`, the oracle/sync/entitlement tests, `engine/tests/fixtures/**`).
  `engine/src/surface.rs` is not on the list, but the oracle freezes its bytes, so T3 runs as Contract
  (`contract-engineer`, `contract-reviewer`). A task that finds it must touch a listed file stops (§9).
- **Commands.** No Tauri command is added or renamed; `run_shell` keeps 29 and `run_console` 71
  (`app/src/main.rs:107`, `:194`; recount at T0). `commands.rs` computes nothing.

## 2. Branches, worktrees, PR, the swap and the red window

- **Integration branch:** `feat/v0.4.0-ui`, worktree `.claude/worktrees/v040-ui` (exists). Only
  `integrator` merges into it, and only a task branch that is green and has its review PASS. **Each task
  lands as one squashed commit** (`git merge --squash`, message `tNN: <what>`), so no red commit ever
  enters the branch's or main's history and `git bisect` sees only green commits (P5). **The red-first
  evidence survives the squash (R2-4):** before the squash the integrator tags the task's red commit
  `v040-red/tNN` (a local tag, kept until the `v0.4.0` tag, then deleted), and the squash commit's body
  carries the red SHA and each red test's failure reason, copied from the ledger. After each merge the
  integrator runs the workspace gate in `v040-ui`. T26 spot-checks `git show v040-red/tNN` for at least
  four tasks against their squash messages.
- **Task branches:** `v040/tNN-<word>` cut from the integration branch's head at dispatch (git cannot
  hold `feat/v0.4.0-ui/…` beside `feat/v0.4.0-ui`). Worktrees `.claude/worktrees/v040-tNN`. At most four
  live builds at once (memory: laptop concurrency); **delete the worktree's `target/` after its merge**
  (each is 13-22 GB). Task branches are local; nothing is pushed until the PR.
- **Spike branch:** `spike/v040-decorum`, worktree `.claude/worktrees/v040-spike`, never merged.
- **The red window.** Every task commits its failing pins first (`test-writer`, commit "red: …"), then
  the code that turns them green. The window opens at that red commit and closes at the green one, **on
  the task branch only**; the squash leaves nothing red on `feat/v0.4.0-ui`, so the integration branch
  and the PR are green at every commit. A pin may assert only files its own task owns (or files already
  merged), so every red window closes on its own branch (P3). Page files exist from T5's merge on as
  one-line placeholders listed in `index.html`, so `every_script_and_link_resolves` is green throughout and
  a page task only replaces its own placeholders (P1). Two known gaps that are not red: from T6's merge to T23's, the branch's
  built app is frameless with the old page (no caption buttons; the 3 s fallback shows it), so no one
  demos the branch in that span; and `next/` is bundled but never loaded until T23.
- **The swap commit** is T23's green commit, message `swap: v0.4.0 page replaces the console (fidelity ledger §7)`,
  after `test-writer`'s red commit on the T23 branch; the squash makes the pair one commit on
  `feat/v0.4.0-ui`. It is green by itself: the move, the deletions, `ROOT = "static"`, `bundle_config.rs`
  and the retired tests land together.
- **The PR:** one, `feat/v0.4.0-ui` → `main`, opened by the main session after T26's PASS. CI runs on it.
  The live proof (§8) runs on the PR head; the merge follows at once with main unmoved (N3's same-tree
  rule); the pre-tag gate runs on the merge SHA; the tag waits for Quinn's word.
- **Ledger:** `.superpowers/sdd/2026-11-17-v040/progress.md`: one row per dispatch (task, branch, red
  SHA, green SHA, each red test's failure reason, test counts, warnings, review verdict, squash SHA).
