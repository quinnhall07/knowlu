## 2. The one-document shell

One `index.html`, loaded once; the sidebar, top band and right panel render once and only `#center`
swaps. Plain scripts, no bundler, no modules.

**Files:** `index.html` (a skeleton: sidebar, top band, `#center`, `#panel`, `#sheet`, `#layer` above
`#sheet`, `#boot`, `#top-note`);
`css/{tokens,shell,slots}.css` plus one CSS file per page or surface; `js/prefs.js` (head, blocking),
`js/{fmt,kit,data,router,shell,boot}.js`; `js/pages/*.js`, `js/carried/*.js`, `js/{wizard,picker}.js`;
`fonts/` with `SOURCES.md` and an OFL per family; `logos/` for the sources v0.4.0 reads only (Blackboard,
Canvas, zyBooks, VHL, Google Calendar, Gmail, Outlook). Every page, sheet, wizard panel and picker
renders its own markup into a host; nothing but M2 edits `index.html` (I8).

- **D1 Router.** Hash routes `#home`, `#tasks`, `#calendar`, `#classes`, `#class/<slug>`, `#lockin`,
  `#settings[/<section>]`. Each module registers itself (`KnowluRouter.add(name, {mount, update,
  unmount})`), so no lane edits `router.js`. Dispatch only through an own-property check. **The
  telemetry `view` is the fixed route name** (`home`, `tasks`, `calendar`, `classes`, `class`, `lockin`,
  `settings`), never the slug: `ui_event` refuses `/`, and `class:<slug>` would tell telemetry what the
  student takes (I9).
- **D2 Transitions.** `document.startViewTransition` around unmount/mount; the sidebar and top band are
  named so they hold still. Reduced motion skips it.
- **D3 Data layer.** `KnowluData.call(cmd, args)` is the one invoke wrapper (envelope, refusal, Undo
  hooks); lanes call it and add nothing to `data.js`. Poll `state` with the page's view (`today` for Home
  and Lock in; `all` for Tasks, Calendar, Classes and a class page, since only horizon views carry
  `list`, `surface.rs:2324-2330`) at launch, on focus and every 60 s (`console.js:3205-3206`). Repaint
  only on a new `revision`. **First run:** while the envelope carries `first_run`, `state` is null
  (`commands.rs:525-533`); the shell shows Home's first-run view and polls every 3 s, as the shipped page
  does (`console.js:1502-1505`), and no page assumes a state (I4). Writes pass the current page's view and
  adopt the returned `state`. `preview_window` is a read: its state feeds the window editor only and never
  replaces the poll's (M4). `mark_seen` stays the end of a look (blur, hidden), never boot
  (`console.js:3207-3213`). A changed order waits for the pointer to leave the list.
- **D4 Preferences before paint.** localStorage keys `knowlu.theme`, `knowlu.font`, `knowlu.text`,
  `knowlu.pin`, `knowlu.cal.zoom`, `knowlu.cal.due`, and no others. `setTheme` also calls
  `getCurrentWindow().setTheme()`.
- **D5 Shipped-file rules.** The CSP is unchanged (`tauri.conf.json:10`): no inline script, no `on*=`, no
  `eval`. No `http(s)://` in shipped `.html`/`.js`/`.css`; the tokens' SVG pattern URIs percent-encode
  their `xmlns` (`system/tokens.css:127-129`); inline SVG drops `xmlns`; logo `.svg` files keep only the
  SVG namespace. `innerHTML` takes a module constant or a string built through `h()`. Mockup aids are not
  ported (`nav.review`, `review.js`, `?state=`, `DEMO_NOW`, made-up names); "now" is `state.now`.
- **D6 Size and zoom.** `.app` keeps `zoom: .88`; "Larger" sets 1.0. Default window 1280 x 800 (from 860,
  `tauri.conf.json:9`), minimum 820 x 600; the window maximizes when the monitor's work area is smaller,
as part of the one show path after first paint (§3, N2).
  **At 820 x 600** the layout is about 932 x 682 CSS px, so the center is about 872 wide with the rail.
  There: Home's two panes stack into one column (right pane under left) below 1000 px of center; Calendar
  opens at 3 days below 1000 px (1 to 7 still choosable; a 7-day column is about 116 px); Classes drops
  Next due below 900 px; a class page and Settings are one column; Lock in scales by its unit (0.7 floor).
  With Larger text the center is about 760, and rows go two-line below 800 (DESIGN.md "Layout in the
  app"). Acceptance at 820 x 600 and 1280 x 800, 100/125/150%, both text sizes: no horizontal scroll;
  `#center` is the only scroller.
- **D7 Fonts.** PT Serif Caption, Albert Sans, OpenDyslexic, all unmodified upstream or Google-served
  files (precedent `app/static/fonts/SOURCES.md:3-10`). Zilla Slab's only app use is Ask, so it does not
  ship. If OpenDyslexic's WOFF2 conversion counts as a Modified Version under its RFN, ship upstream
  `.woff`. Instrument Sans and JetBrains Mono go at the swap.

## 3. Window chrome

Ruling 4: frameless. Only `main` changes; `mail`, `mail-popup`, `lms-grades`, `lms-signin` keep their
native frames.

**Config** (`tauri.conf.json:9`, `main`): `"decorations": false`, `"width": 1280, "height": 800`,
`"center": true`, `"visible": false`. No `backgroundColor`: a fixed colour flashes in one theme or the
other (M9).

**Window state (B1, N2).** Both builders (`main.rs:90`, `:148`) use the plugin's default flags, which
restore `decorated` (a saved `"decorated": true` would put a native bar over the drawn one) and restore
`MAXIMIZED` at window-ready through `ShowWindow(SW_MAXIMIZE)`, which makes a hidden window visible
before WebView2 paints (r2 N2). Both become `Builder::default().with_state_flags(FLAGS)
.skip_initial_state("main").build()`, with `FLAGS = StateFlags::all() & !StateFlags::DECORATIONS &
!StateFlags::VISIBLE`: the frame is always the config's, and the plugin never touches `main` at
creation. The other windows keep the plugin's normal restore. Saving on close is unchanged. The
saved file is `%APPDATA%\com.knowlu.desktop\.window-state.json`, one per Windows user (settled by r2).

**The one show path (N2, N9).** One Rust function, `show_main` in `main.rs`, run once per process (an
`AtomicBool`): restore `main` with `FLAGS` (the plugin's `restore_state`), maximize when the monitor's
work area is smaller than the window (D6) and the restored state is not already maximized, set the
border (below), then `show()` and `set_focus()`. Two triggers, registered in **both** builders
(`run_shell` shows the wizard and picker too): the page's `ui-ready` event, emitted by `boot.js` once the
theme class is set, after `DOMContentLoaded` plus one `requestAnimationFrame`, racing a 300 ms timeout
(whether rAF fires while the host window is hidden is not settled by code); and a 3 s timer from setup,
so a script error can never leave an invisible app. The event is listened for in Rust
(`app.listen`), so no Tauri command is added and `run_shell` keeps its 29; `core:default` already grants
the page `emit` (tauri 2.11.5 `build.rs:33-40`, `:452-466`; settled by plan review r1).
The single-instance `show()` (`main.rs:89`, `:147`) is untouched; autostart passes only `--vault`
(`main.rs:150`). A Rust source pin (`window_chrome.rs`) checks both builders use `FLAGS` and
`skip_initial_state("main")` and register both triggers. The proof records time-to-show (§10).

**Drawn chrome** (SHELL.md "Window chrome in the real app (Tauri v2)"): `.side-head` and `.top` carry
`data-tauri-drag-region="deep"` (drag runs the OS move loop, so drag-to-top snaps and drag-out-of-maximized
are native; double-click maximizes); `.wc` holds minimize, maximize/restore and close through
`getCurrentWindow()`, with `isMaximized()` for the glyph. `close()` emits `CloseRequested` (settled in
r1), so main still hides to the tray (`main.rs:187-192`). tao hit-tests the edges of an undecorated
resizable window. The wizard and picker run in `main` and get the same band.

**Border.** On Windows 11 the undecorated window keeps DWM's shadow and corners but shows a 1px light
border. `show_main` calls `DwmSetWindowAttribute(hwnd, DWMWA_BORDER_COLOR (34), &DWMWA_COLOR_NONE
(0xFFFFFFFE), 4)` through the `windows` 0.62 crate the app already uses (`app/Cargo.toml:92`, adding
`Win32_Graphics_Dwm`, which pulls in `Win32_Graphics`). tauri's `WebviewWindow::hwnd()` returns windows
0.61's `HWND` (`tauri-2.11.5/src/window/mod.rs:1668`), so M3b converts through the raw pointer
(`HWND(w.hwnd()?.0)`); nothing in `app/src` calls `hwnd()` today. On Windows 10 the call fails quietly
and the border stays.

**Capabilities** (`capabilities/default.json:5-6`, the one file): add `core:window:allow-minimize`,
`allow-toggle-maximize`, `allow-close`, `allow-start-dragging`, `allow-set-theme`. No `allow-show`: Rust
shows the window. Nothing else changes, so `mail_window.rs:66-104`'s main-only pin stays true. M3b moves
the exact-list pin `the_page_is_granted_no_updater_permission` (`static_assets.rs:1204-1214`) out of
`static_assets.rs` into `window_chrome.rs` with the new list, so the swap's delete cannot take it (N6);
no `updater:` permission.

**Snap layouts spike** (M3a, half a day). The Windows 11 flyout needs a native `HTMAXBUTTON` hit-test.
Try `tauri-plugin-decorum` on a scratch branch; accept it only with a release for tauri 2.11, a
permissive licence, no remote fetch, nothing injected into or granted to the other windows, permissions
under `main` only, 0 warnings. **Fallback:** the plain band, without the flyout (A7). **Acceptance bar**
(on the exe; no agent sends synthetic input or posts window messages, so **Quinn checks drag, snap,
double-click and resize by hand** during the live proof, and the rest is seen by `PrintWindow` and the
DOM): drag, snap to halves and corners,
drag out of maximized; double-click maximizes; every edge and corner resizes to 820 x 600; minimize,
maximize/restore and close-to-tray, with the glyph following; maximized leaves the taskbar; shadow and
rounded corners with no light border; no flash in either theme on a cold start, including a start that
restores maximized and one on a work area smaller than 1280 x 800; time-to-show recorded; the flyout
present (decorum) or its absence recorded.

## 4. Page-to-data map

`S.` is the envelope's state (`surface.rs:2238-2276`); a row is a `Row` (`surface.rs:819-847`: `due`
`YYYY-MM-DDTHH:MM`, `hours` remaining, `course` the slug). **Check** is `set_fields {progress: 100,
status: "done"}` (`console.js:1878-1880`); Undo restores the old progress with `status: "active"`. A
done check fills with the row's class colour (DESIGN.md), never gray; with no course entry, ink (A8).
Minutes are `hours x 60`; dates use one `fmt.js` rule with "now" from `S.now`. A class's mark, code and
colour come from `S.courses` by `row.course`; an unknown course shows the slug and an ink mark. **Active
class:** `status` absent or `active`, as the engine reads it (`commitments.rs:867-869`) (M1).
**Commitment to class (M2, N7):** `compact(course)` (ASCII letters and digits, uppercased, the
engine's rule, `commitments.rs:594-599`) is looked up in each entry's `codes` (§7), which are the
engine's own code table for that slug; with no match the block draws neutral. This is the lookup
`course_key` makes (`commitments.rs:2531-2537`), so a title like "CS 100 – Intro", an LMS `code:` and a
`course_map` key all match.

**Shell.** Sidebar links: active `S.courses`. Clock: `S.now`. Status dot and list: `S.issues_panel.sources`,
`S.warnings` (amber), `grades_status` and `mail_status` with the poll, `google_status` on Settings
mount only, since it calls the network, as shipped (`console.js:2347-2352`; M5, P4); the Status list's
Google line shows what the last Settings visit read, or nothing. "Updated": `S.topline.last_slot`. No Ask control.

## 7. The `courses` read-model field

A new `State` member beside `grades` (`surface.rs:2271-2272`), skipped when empty so the three oracle
vaults (none has `courses/`) serialise exactly as before:

```rust
#[serde(skip_serializing_if = "Vec::is_empty")]
pub courses: Vec<CourseEntry>,

pub struct CourseEntry {
    pub slug: String,             // `slug:`, else the file stem (grades.rs:775-776)
    pub title: String,            // `title:`, else the slug: the code ("CS 100"), scaffold.rs:830
    pub name: Option<String>,     // `name:`, the school's name
    pub status: Option<String>,   // `status:` as written; absent means active (M1)
    pub slot: String,             // "c1".."c16"
    pub standing: Option<String>, // "behind" | "tight" | "steady" | "ahead"; null with no open task
    pub codes: Vec<String>,       // compact codes the engine maps to this slug, sorted (N7)
}
```

**Codes (N7).** `commitments::code_table(vault)` (`engine/src/commitments.rs:711`, public) already maps
each compact code to the slug that claimed it, from every course note's `code`, `title`, `name` and slug
and from `config/ingest.yaml`'s `course_map` (`:754-778`). `codes` is the table's keys whose value is
this slug, in the map's (sorted) order: a few lines, no new rule. An LMS `code:` reaches the page only as
its compact form, which commitments already carry; the table's warnings stay where they are today.

Course notes carry `title`, `name`, `slug`, `code`, `status` (`app/src/scaffold.rs:830-843`); `code` is
the LMS key and is not a field of its own (only its compact form, in `codes`); there is no term field. **Order** is `grades::course_grades`'s, `(title
lowercased, title, slug)` (`engine/src/grades.rs:781`). **Slot:** sort by `slug` (bytes), the i-th
gets `c{(i mod 16) + 1}`: positional so up to 16 classes get distinct colours, by slug because a title
can be edited. Adding a course can shift the colours of those after it; a stored `slot:` is v0.5.0.

**Standing** (ruling 5). Nothing in `state` judges a class; the vault-wide word is
`status_word(runway_days(l.ranked))` (`surface.rs:398-407`, `:470-471`). The smallest honest substitute
is the same rule per class: runway is the minimum `slack_days` over the class's dated active tasks
(`render.rs:286-301`, `scheduling.rs:104-109`); `behind` under 0, `tight` to 1 day, `steady` to 4,
`ahead` above (`render.rs:72-82`). No active task: null. Active but undated: 999 (`scheduling.rs:20`),
so `ahead`, as the vault-wide word does. Quinn accepted this rule (A3).

## 12. What must not break

- **CLAUDE.md's two rules.** No name, class, vault or account in a shipped file; the mockups' made-up
  data does not ship; nothing from Quinn's real classes enters a test, fixture or doc. The eight Python
  references and the three `surface-today-*.json` stay byte-identical (§7).
- **VISION.** Grades as text, never a ring; nothing the student sees needs the network; failures stay
  visible (Status dot, sync line, unreadable notes, overload); checks and edits act at once with Undo,
  Knowlu's proposals wait in Waiting; preferences hold no plan data.
- **Commands.** Every name, argument and casing the old page sent; `commands.rs` computes nothing; every
  vault write goes through a command and `write`.
- **Security and privacy.** The CSP; capabilities to `main` only, no `updater:`; `open_external`
  wizard-only; untrusted text through `h()`; no free text or slug in `ui_event`; re-consent cannot be
  dismissed, never hides today's page and leaves Delete my data reachable; the update-owed lock on every
  start control; the wizard's privacy sentence equals the site's; the four legal pages untouched by the
  port.
- **Window state.** The plugin never restores the frame, never shows `main` before first paint, and a
  saved maximized or small-screen start shows no flash (B1, N2).
- **Money.** The app and the site's pages outside the legal ones state no price, trial length or plan
  price until billing and terms move together in v0.5.0 (A2; §13).
- **Release.** `com.knowlu.desktop`, NSIS `currentUser`, updater endpoint and pubkey, one version in two
  places; CI-only releases from a SHA that passed the pre-tag gate; 0 warnings, LF for `app/static`,
  SHA-pinned actions; release.yml's signing and secrets unchanged.
- **Wizard.** Its 29 commands, its flow, every credential path.
